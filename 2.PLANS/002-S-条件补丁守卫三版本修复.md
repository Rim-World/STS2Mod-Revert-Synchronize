# 三版本兼容修复：条件补丁守卫

- 日期：2026-11-13
- 状态：待实施（已按独立审查修订）
- 目标版本：v1.2.1
- 关联：`3.DOCS/002-R-加载期CanonicalKeywords补丁异常.md`

## 背景

正式版当前为 0.107.x，官方计划把正式版内容切换到原 beta 0.111.x，beta 线已到 0.113.x。本 mod 的 `min_game_version` 为 0.107.0，0.107 / 0.110 / 0.111 / 0.113 都会加载。

当前缺陷是加载期记 ERROR：0.107 专属的条件补丁用错了查找方式。

## 版本事实

| 版本 | `Synchronize.CanonicalKeywords` | `CardModel.GetResultPileTypeForCardPlay` | 证据 |
|---|---|---|---|
| 0.107 | `public override`，返回 `[Exhaust]` | 存在（`protected virtual`，声明在 `CardModel`） | `1.STS2-107Reference/.../Cards/Synchronize.cs:28`；`.../CardModel.cs:2070` |
| 0.110 | 无 override | 无；改用 `GetResultLocationForCardPlay()` | `4.STS2-Decompiled/decompiled-full/MegaCrit/sts2/Core/Models/Cards/Synchronize.cs`；`.../CardModel.cs:2085` |
| 0.111 | 无 override | 无 | `2.STS2-111Reference/.../Cards/Synchronize.cs`；`.../CardModel.cs:2084` |
| 0.113 | 无 override | 无 | `3.STS2-113Reference/.../Cards/Synchronize.cs`；`.../CardModel.cs:2263` |

`CardModel.CanonicalKeywords` 三版本都是 `public virtual`（107 `:498`、111 `:499`、113 `:579`）。

## 语义核对（2026-11-13 修订）

- `AccessTools.PropertyGetter(Type, string)` 沿继承链查找；`AccessTools.DeclaredPropertyGetter(Type, string)` 只查该类型自身声明的成员。
- Harmony 2.4.2 的拒绝条件是 `PatchProcessor.Patch()` 中的 `IsDeclaredMember()`，即 `DeclaringType == ReflectedType`。**任何**通过派生类型拿到的继承成员（虚方法、非虚属性都一样）都会被拒绝，不只是「基类虚方法」。
- 0.107：`Synchronize` 自身声明 override，两种查找都命中，`DeclaringType == ReflectedType`，可以打补丁。
- 0.110 / 0.111 / 0.113：`Synchronize` 不声明该成员，`DeclaredPropertyGetter` 返回 `null`，按原意跳过；旧写法会拿到 `DeclaringType = CardModel` 的继承 getter，Harmony 抛 `ArgumentException`。
- 同样的模式也存在于第二个条件补丁（`AccessTools.Method`）与形状守卫中的 `typeof(Synchronize)` 检查；今天没触发只是因为目标恰好声明在预期类型上。

## 问题

`9.SRC/RevertSynchronize/ModEntry.cs:38-40` 用 `AccessTools.PropertyGetter` 探测「107 专属成员」。0.110 及以上返回继承成员，Harmony 拒绝并抛 `ArgumentException`（`ModEntry.cs:65`），外层 `catch` 记 ERROR：

- 主补丁（`PatchAll`）已成功应用；
- 第二个条件补丁不再执行；
- `Harmony patches applied` 汇总日志不再输出。

现有 `godot.log:425-435` 是同一条异常（加载的是工坊 v1.0 副本，代码与本地 v1.2 相同），栈行号与源码一致。

## 方案

1. **必须**：`ModEntry.cs:38-40` 改用 `AccessTools.DeclaredPropertyGetter`。
2. **建议**：第二个条件补丁改用 `AccessTools.DeclaredMethod`（同类缺陷，今天行为不变）。
3. **建议**：`SynchronizeShapeGuard.ValidateStatic()` 的 12 项检查统一改用 `AccessTools.DeclaredPropertyGetter` / `AccessTools.DeclaredMethod`，让守卫与 `PatchAll` 的解析口径一致；今天三版本仍全部通过。
4. **建议**：`PatchIfExists` 增加 per-patch `try/catch`，`Log.Error` 写明目标成员、补丁类型与方法名、异常消息，并返回 `false`；不中断后续条件补丁与汇总日志。
5. **版本号**：`1.2` → `1.2.1`，顺带消除 `not a valid Semantic Version` 告警（仅在加载 1.2.1 副本时生效）。

## 不做

- 不删除 `CanonicalKeywords` 条件补丁：保留「清空 canonical 源头」的防御价值。
- 不改关键词过滤、数值、文本补丁。
- 不设置 Harmony 优先级：当前没有全局改写关键词的 mod 与它叠加。
- 不在本计划内修 0.107 `ResultPile` 的 dupe 副作用（见「既有缺陷」）。

## 既有缺陷（不在本计划范围）

`SynchronizeResultPilePatch.Postfix107` 对**所有** Synchronize 强制 `PileType.Discard`，包括 dupe。`HistoryCourse` 遗物自动打出的 dupe 因此不会被移除，等于永久多一张同步。该问题只在 0.107 出现，且不是本次改动引入。若决定修，最小改法是仅当 `__result == PileType.Exhaust` 时替换为 `Discard`；需要用户确认是否纳入。

## 验证方法

1. 静态：确认四个版本是否声明 override / `GetResultPileTypeForCardPlay`。
2. 构建：以当前 0.113 `sts2.dll` 为基线，0 警告 0 错误。
3. 运行：0.113 启动一次，检查日志与卡面；0.107 可切换分支验证；0.110 / 0.111 无本地环境，标记未验证。
4. 0.107 的 `0Harmony.dll` 版本需实机确认提供 `DeclaredPropertyGetter`（自 Harmony 2.x 早期存在，风险低）。
