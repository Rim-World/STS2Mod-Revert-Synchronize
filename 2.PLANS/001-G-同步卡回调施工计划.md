# 计划：RevertSynchronize —— 将「同步」整卡回调至 v0.110 效果

状态：调研完成 → 用户拍板（2026-08-16）→ v1.0 已构建安装 → v1.1 修复 107 虚分派问题 → **v1.2 关键词全路径下沉 + 打出判定钉死 + 诊断日志（2026-08-16）**，待游戏内复测

## 一、背景与目标

杀戮尖塔 2 故障机器人技能牌「同步」（Synchronize）在 v0.111.0 被削弱：
每种不同的充能球获得的本回合临时集中从 **2（升级 3）→ 1（升级 2）**。
需求：整卡回调至 v0.110 效果（基础 2 / 升级 3，无消耗），覆盖卡牌所有形态
（基础版、升级版、图鉴预览），并在 v0.110.x 上不生效（该版本本就是目标效果）。

- mod 命名：`RevertSynchronize` / 「回调同步（RevertSynchronize）」
- 作者：再玩小卡组找人弄你；版本 1.0；图标：空白占位（420×420）
- 工程位置：`C:\Users\13167\Desktop\Mod\STS2Mod-回调同步`（独立目录，仿 STS2Mod-至亮之焰）

## 二、已取证结论

### 2.1 三版本「同步」差异（反编译逐行 diff）

| 版本 | 基础 | 升级 | 消耗 | 源码出处 |
|---|---|---|---|---|
| v0.107 | Extra=2（2×种类） | 仅移除消耗，不加值 | 基础有 | `decompiled-107` |
| v0.110 | Extra=2（2×种类） | Extra+1 → 3×种类 | 无 | `decompiled-full` |
| v0.111 | Extra=1（1×种类） | Extra+1 → 2×种类 | 无 | `decompiled-111` |

- 集中值公式（`CalculatedVar.Calculate` 反编译实证）：
  `集中 = CalculationBase(0) + CalculationExtra × 不同充能球种类数（按 Orb.Id 去重）`
- `SynchronizePower : TemporaryFocusPower`（本回合临时集中）三版本一致，无需改动。
- 官方补丁笔记（提取自本机 v0.111.0 `SlayTheSpire2.pck` 内 patch_notes）：
  - `2026_07_30`（v0.110）：Buffed Synchronize — 升级临时集中 2→3；不再消耗。
  - `2026_08_13`（v0.111）：Nerfed Synchronize — 集中 2(3) → 1(2)。

### 2.2 卡面文本（111 官方 pck 16 语言原文，模板变量驱动）

描述模板不含数字，数值由 DynamicVars 渲染；111 仅改数值未改模板（补丁笔记无文字改动）。
zhs 模板：

> `你每有一种不同的充能球，就在本回合获得{CalculationExtra:diff()}点[gold]集中[/gold]。{InCombat:\n（获得{CalculatedFocus:diff()}点[gold]集中[/gold]）|}`

→ 补丁后渲染为 110 文本：基础「…获得 2 点集中」（战斗中显示 2N），升级 3/3N。
16 语言原文存档见 `languages/raw/` 与 `languages/原文汇总.md`（tha 缺 title 键，按游戏规则回退 eng）。

### 2.3 版本门槛与版本门

- manifest `min_game_version = 0.107.0`（加载器原生拒绝更低版本）。
- 运行时版本门：`ReleaseInfoManager.Instance.SemVer`（`MegaCrit.Sts2.Core.Debug`，
  111 反编译实证 `Major/Minor/Patch` 属性）判 `0.110.x`（Major=0 且 Minor=110）→ 补丁不生效。

## 十、v1.2 修复记录（2026-08-16，107 打出仍消耗 · 第二轮）

**现象（107 实测）**：基础版与升级版打出后仍进消耗区；图鉴卡面文本带"消耗"，对局卡面文本无消耗；
日志确认补丁已应用、版本门放行（v0.107.1）。

**分析**：打出判定唯一路径 = `PlayCardAction → OnPlayWrapper → GetResultPileTypeForCardPlay`
（107，返回 PileType）/ `GetResultLocationForCardPlay`（110/111，返回 CardLocation），内部均走
`Keywords.Contains(Exhaust)`（v1.1 已过滤）。图鉴（NCardLibrary）与对局（NCard）文本均经
`GetDescriptionForPile` → `Keywords`，静态上 v1.1 过滤应同时覆盖三者，与实测矛盾——
说明 107 上存在**未经过 `Keywords` getter 的关键词读取路径**（canonical 实例 LocalKeywords 缓存、
`GetKeywordsWithSources(Local)` 直接调用、第三方 mod hook 等）。

**修复（v1.2）**：
1. 关键词过滤**下沉**到 `CardModel.GetKeywordsWithSources`（三版本同名方法、一切关键词读取的必经点）
   —— 覆盖 Keywords 属性内部、图鉴/预览、克隆、打出判定等全部路径；
2. **条件补丁** `Synchronize.CanonicalKeywords`（107 特有 override，ModEntry 手动挂载）→ 源头清空，
   使 canonical 实例 LocalKeywords 缓存首次填充即为空；
3. **条件补丁** `GetResultPileTypeForCardPlay`（107）→ Postfix 钉死 `PileType.Discard`，
   打出结果无条件进弃牌堆（110/111 不钉死：其判定走已过滤的 Keywords，且避免引用 107 不存在的 CardLocation 类型）；
4. 首触发**诊断日志**（过滤前后集合、实例类型/canonical/战斗状态），条件补丁挂载状态日志；
5. manifest 版本 → `1.2.0`（消除"非合法语义化版本"警告）。

**验证**：DLL 0 警告 0 错误；元数据确认新旧挂点；已重新安装。待 107 复测 + 日志回传。

## 九、v1.1 修复记录（2026-08-16，107 打出后仍消耗）

**现象**：107 版本实测基础版打出后依然进消耗区（111 正常）。

**根因**：v1.0 的关键词补丁打在 `CardModel.CanonicalKeywords` getter（基类）上；
107 的 `Synchronize` 类 **override** 了 `CanonicalKeywords`（返回 `[Exhaust]`），虚方法分派
使实例调用直接走 override、不经过基类 getter → 补丁在 107 上不触发 → Exhaust 进入
`LocalKeywords` 实例缓存（`_keywords.UnionWith(CanonicalKeywords)`）→
`GetResultLocationForCardPlay()` 按 `Keywords.Contains(Exhaust)` 判定 → 打出消耗。
110/111 的 Synchronize 无 override（走基类），故 111 正常。

**修复**：`SynchronizeKeywordsPatch` 改挂 `CardModel.Keywords` getter
（三版本均非 virtual、Synchronize 均不 override，所有读取 100% 经过）→ Postfix 过滤
`__result` 中全部 Exhaust（覆盖 107 override 缓存、战斗 hook 等一切来源）；
守卫成员检查同步改为 `Keywords`。版本 1.0 → 1.1。

**验证**：DLL 0 警告 0 错误；DLL 元数据已无 `CanonicalKeywords` 字符串、`Keywords` 挂点存在；
已重新安装至游戏 mods 目录。待游戏内回归（107 + 111 各测一遍）。
