# 001-总体设计：RevertSynchronize

- 记录时间：2026-08-16
- 对应版本：manifest 记录 `1.2.2`
- 来源：`9.SRC/RevertSynchronize/` 源码、`1.ADR/001-同步卡回调至v0.110方案.md`、`3.DOCS/001-T-同步卡三版本差异调研.md`

本文件内容全部提炼自上述源码与文档；源码中没有的事实标注「未记录」，不做推断补全。

## 一、设计目标

1. 将《杀戮尖塔 2》故障机器人技能牌「同步」（`Synchronize`）整卡固定为 v0.110 定义：1 费、技能牌、目标自身、罕见、无消耗，基础每有一种不同充能球获得 2 点本回合集中，升级后 3 点。
2. 覆盖卡牌的全部形态：基础版、升级版、图鉴预览与战斗内卡面文本。
3. 在 v0.110.x 上不生效，因为该版本卡牌本身就是目标效果。
4. 直接在原卡上修改，不生成新卡牌、不禁用旧卡牌；不改写卡图。
5. 不依赖任何基础 mod，采用最小依赖实现。

## 二、模块划分

| 层 | 模块 | 文件 | 职责 |
|---|---|---|---|
| 入口 | `ModEntry` | `ModEntry.cs` | `[ModInitializer("ModLoaded")]` 入口；执行顺序为静态守卫 → `Harmony.PatchAll` → 条件补丁挂载 → 日志；全流程 `try/catch` 兜底 |
| 开关 | `ModConfig` | `ModConfig.cs` | 总开关 `IsReplaceEnabled`＝形状守卫 `IsSupported()` 且版本门 `IsActiveVersion()`；版本结论懒求值并缓存 |
| 守卫 | `SynchronizeShapeGuard` | `Patches/SynchronizeShapeGuard.cs` | 静态成员存在性检查（`ValidateStatic`）＋运行时 `ModelDb.Card<Synchronize>()` 检查（`IsSupported`） |
| 补丁 | 数值与行为 | `Patches/SynchronizeCorePatches.cs` | `CanonicalVars`、`OnPlay`、`OnUpgrade` 三个补丁 |
| 补丁 | 关键词 | `Patches/SynchronizeKeywordsPatch.cs` | `CardModel.GetKeywordsWithSources` Postfix（主挂点），另含两个仅 107 挂载的条件补丁 |
| 补丁 | 元数据 | `Patches/SynchronizeMetaPatches.cs` | 费用、类型、目标、稀有度、悬停提示 |
| 补丁 | 文本 | `Patches/SynchronizeTextPatches.cs` | 卡名与描述切换到 `RE_SYNCHRONIZE.*` 本地化键 |
| 资源 | 本地化 | `RevertSynchronize/localization/<lang>/cards.json` | 16 语言（deu、eng、esp、fra、ind、ita、jpn、kor、pol、ptb、rus、spa、tha、tur、zhs、zht）卡名与描述模板 |
| 资源 | 图标 | `RevertSynchronize/mod_image.png` | 420×420 的 mod 图标，与 `pics/Synchronize_small.png` 字节相同；`TOOLS/scripts/gen-blank-icon.py` 可生成同尺寸的全透明占位图 |
| 构建 | 工程配置 | `RevertSynchronize.csproj`、`project.godot`、`export_presets.cfg`、`build.ps1` | Godot.NET.Sdk 4.5.1 / net9.0 工程；pck 导出预设与构建脚本 |

模块依赖方向：`ModEntry` → {`SynchronizeShapeGuard`, 各补丁类} → `ModConfig` → `SynchronizeShapeGuard`。
所有补丁体在入口处判断 `ModConfig.IsReplaceEnabled`，为假时直接返回、不修改原版行为。

## 三、补丁策略

全部补丁自包含，不读取原版实现。目标成员与行为：

| # | 补丁类 | 目标 | 行为 |
|---|---|---|---|
| 1 | `SynchronizeCanonicalVarsPatch` | `Synchronize.CanonicalVars` getter，Postfix | 整体替换为 `CalculationBaseVar(0m)`、`CalculationExtraVar(2m)`、`CalculatedVar("CalculatedFocus")`（乘数＝按 `Orb.Id` 去重后的充能球种类数） |
| 2 | `SynchronizeOnPlayPatch` | `Synchronize.OnPlay`，Prefix 替换 | `CreatureCmd.TriggerAnim(..., "Cast", ...)` → 计算 `CalculatedFocus` → `PowerCmd.Apply<SynchronizePower>`，SkipOriginal |
| 3 | `SynchronizeOnUpgradePatch` | `Synchronize.OnUpgrade`，Prefix 替换 | `DynamicVars.CalculationExtra.UpgradeValueBy(1m)`，SkipOriginal |
| 4 | `SynchronizeKeywordsPatch` | `CardModel.GetKeywordsWithSources`，Postfix | 目标卡为 `Synchronize` 时过滤 `CardKeyword.Exhaust`；首触发打印诊断日志 |
| 5 | `SynchronizeCanonicalKeywordsPatch` | `Synchronize.CanonicalKeywords` getter，条件挂载 | 107 专有 override，返回空集合，使源头不再产生 `Exhaust` |
| 6 | `SynchronizeResultPilePatch` | `CardModel.GetResultPileTypeForCardPlay`，条件挂载 | 107 专有方法，Postfix 将结果钉死为 `PileType.Discard` |
| 7 | `SynchronizeEnergyCostPatch` | `CardModel.CanonicalEnergyCost` getter，Postfix | 固定为 `1` |
| 8 | `SynchronizeEnergyCostCanonicalPatch` | `CardEnergyCost.Canonical` getter，Postfix | 经私有字段 `_card` 判定目标卡，固定为 `1` |
| 9 | `SynchronizeTypePatch` | `CardModel.Type` getter，Postfix | 固定为 `CardType.Skill` |
| 10 | `SynchronizeTargetTypePatch` | `CardModel.TargetType` getter，Postfix | 固定为 `TargetType.Self` |
| 11 | `SynchronizeRarityPatch` | `CardModel.Rarity` getter，Postfix | 固定为 `CardRarity.Uncommon` |
| 12 | `SynchronizeHoverTipsPatch` | `Synchronize.ExtraHoverTips` getter，Postfix | 固定为 `HoverTipFactory.FromPower<FocusPower>()` |
| 13 | `SynchronizeTitlePatch` | `CardModel.TitleLocString` getter，Postfix | 返回 `LocString("cards", "RE_SYNCHRONIZE.title")` |
| 14 | `SynchronizeDescriptionPatch` | `CardModel.Description` getter，Postfix | 返回 `LocString("cards", "RE_SYNCHRONIZE.description")` |

补丁 5、6 不参与 `PatchAll`，由 `ModEntry.PatchIfExists` 在目标成员存在时才挂载；挂载结果写入启动日志。

## 四、数据流

1. 游戏加载 mod，回调 `ModEntry.ModLoaded`。
2. `SynchronizeShapeGuard.ValidateStatic` 检查 `CardModel` 与 `Synchronize` 的全部补丁目标成员；失败则打印 Warn 并结束，不挂载任何补丁。
3. 静态检查通过后执行 `Harmony.PatchAll`，再按存在性挂载条件补丁。
4. 卡牌属性读取（费用、类型、目标、稀有度、关键词、标题、描述）经 `CardModel` / `CardEnergyCost` getter 的 Postfix 覆盖返回值。
5. 标题与描述返回 `RE_SYNCHRONIZE.*` 键，由游戏本地化系统按当前语言取模板；模板内 `{CalculationExtra:diff()}` 与 `{CalculatedFocus:diff()}` 由第 1 项补丁写死的 DynamicVars 渲染，因此文本显示基础 2、升级 3。
6. 打出时 `OnPlay` 被整体替换：播放施法动画后按 `CalculatedFocus` 施加 `SynchronizePower`（`TemporaryFocusPower`，本回合有效），层数＝额外值 × 不同充能球种类数。
7. 升级时 `OnUpgrade` 被整体替换：额外值 +1，升级后为 3 × 种类数。
8. 关键词读取统一经 `CardModel.GetKeywordsWithSources`，Postfix 在此过滤 `Exhaust`，因此图鉴、战斗内卡面与打出判定三者一致。

## 五、数据结构

- 卡牌数值：`DynamicVars` 含 `CalculationBaseVar(0m)`、`CalculationExtraVar(2m)`、`CalculatedVar("CalculatedFocus")`；`CalculatedFocus = CalculationBase + CalculationExtra × 不同充能球种类数`。
- 本地化键：`RE_SYNCHRONIZE.title`、`RE_SYNCHRONIZE.description`；`RE_` 前缀用于避免与其他 mod 覆盖 `SYNCHRONIZE.*` 键时冲突。
- manifest 字段（`RevertSynchronize.json`）：`id`、`name`、`author`、`description`、`version`、`has_pck`、`has_dll`、`min_game_version`、`dependencies`、`affects_gameplay`。当前 `version` 为 `1.2.2`，`min_game_version` 为 `0.107.0`，`dependencies` 为空数组。

## 六、异常处理与降级

| 情形 | 处理 | 结果 |
|---|---|---|
| 静态成员缺失（未来版本改结构） | `ValidateStatic` 返回假并打 Warn | 不挂载补丁，游戏保持原版，不崩溃 |
| 条件补丁目标不存在 | `PatchIfExists` 返回假，启动日志记录 `CanonicalKeywords(107)=…, ResultPile(107)=…` | 跳过该补丁 |
| `PatchAll` 抛异常 | `ModLoaded` 内 `try/catch` 记 Error | 不向游戏抛出 |
| 版本号读取异常 | `ModConfig` 记 Warn，暂按「非 110」放行，下次访问重试 | 补丁继续生效 |
| `ModelDb` 尚未就绪 | `IsSupported` 暂返回真，结论不缓存 | 下次访问重新评估 |

## 七、兼容策略

1. 版本门槛：manifest `min_game_version=0.107.0`，由加载器拒绝更低版本。
2. 版本门：`ReleaseInfoManager.Instance.SemVer` 判定 `Major == 0 && Minor == 110` 时禁用全部补丁；该判断含 0.110.x 的全部补丁号。
3. 三版本统一：v0.107 的基础版带 `Exhaust`、升级只移除消耗不加值，v0.111 数值为 1/2；上述差异由写死的数值、关键词与升级补丁吸收，三次版本表现一致。
4. 关键词读取路径：主挂点选 `GetKeywordsWithSources`，避免 107 对 `CanonicalKeywords` 的 override 造成虚分派绕过（详见 `3.DOCS/001-T-同步卡三版本差异调研.md`）。
5. 资源冲突：本地化键使用 `RE_` 前缀；卡图不自带、交由原版渲染。
6. 未记录：与第三方 mod 同时改写同一张卡牌时的优先级与冲突处理。

## 八、构建与打包

- 工程：`Godot.NET.Sdk/4.5.1`，`net9.0`，`ImplicitUsings` 与 `Nullable` 开启，`AllowUnsafeBlocks` 开启。
- 引用：从游戏目录 `data_sts2_windows_x86_64` 引用 `sts2.dll` 与 `0Harmony.dll`，`Private=false`（不打入产物）。
- `project.godot`：`config/name="RevertSynchronize"`，`project/assembly_name="RevertSynchronize"`，渲染方式 `mobile`。
- `export_presets.cfg`：`Windows Desktop` 预设，`export_filter="resources"`，`export_files` 显式列出 `res://RevertSynchronize/mod_image.png` 与 16 个 `cards.json`，`binary_format/architecture="msil"`，不加密 pck。
- `build.ps1`：`dotnet build -c Debug -p:NuGetAudit=false` → Godot headless `--import` → `--export-pack "Windows Desktop"` 生成 pck → 拷贝 `dll`、`pdb`、`json` 到游戏 `mods\RevertSynchronize`。
- 产物：`RevertSynchronize.dll`、`RevertSynchronize.pck`、`RevertSynchronize.pdb`、`RevertSynchronize.json`。本地暂存于 `10.OUTPUT/01-构建产物/`，同时已安装到游戏 mods 目录。

## 十一、v0.113 兼容修复（2026-11-13）

- 条件补丁探测从 `AccessTools.PropertyGetter` / `Method` 改为 `DeclaredPropertyGetter` / `DeclaredMethod`，避免命中继承成员导致 Harmony 拒绝。
- 形状守卫同步改用 `Declared*`，与 `PatchAll` 口径一致。
- `PatchIfExists` 增加逐补丁异常隔离，单个目标失败不再中断后续补丁和汇总日志。
- 清单版本升至 `1.2.1`；0.113 启动验证显示两个 107 专属补丁均按预期为 `False`。


## 十二、v1.2.2 `ResultPile` dupe 修复（2026-11-13）

- 0.107 `GetResultPileTypeForCardPlay()` 对 dupe 返回 `PileType.None`，结算时走 `RemoveFromCombat`。
- 旧 Postfix 无条件改为 `PileType.Discard`，使 `HistoryCourse` 自动打出的同步 dupe 留在弃牌堆。
- 现改为仅当 `__result == PileType.Exhaust` 时替换为 `Discard`；`None`、`Discard` 等结果保持不变。
- 0.110 / 0.111 / 0.113 没有该方法，补丁不挂载；0.113 行为不变。
